# Claude Code 저장소 선택 및 사용 가이드

Claude Code on the web(claude.ai/code)에서 세션을 시작할 때 "어떤 저장소를 골라야 하는지", "골라 놓은 저장소를 어떻게 쓰는지", "작업마다 새 저장소가 필요한지"에 대한 실전 가이드입니다.

## 1. 저장소는 언제, 어떻게 선택하나요?

- 저장소는 **세션을 생성하는 시점**에 지정합니다. 세션 생성 화면(또는 `create_session`)에서 GitHub 저장소를 선택하면, 그 세션은 해당 저장소로 스코프(scope)가 고정됩니다.
- 세션이 접근할 수 있는 저장소 목록은 **세션 시작 시점의 스냅샷**입니다. 즉, 세션 중간에 다른 저장소가 필요해지면 자동으로 열리지 않고, `add_repo`로 명시적으로 추가해야 합니다.
- 아직 이 계정/세션에 연결되지 않은 저장소를 쓰고 싶다면 `list_repos`로 접근 가능한 저장소 목록을 먼저 확인하세요. 목록에 없다면:
  - GitHub 계정이 연결되어 있는지 확인 (claude.ai/connect-github)
  - 해당 저장소(또는 조직)에 Claude GitHub App이 설치되어 있는지 확인 (github.com/apps/claude/installations/select_target)
- 로컬 CLI(터미널)로 쓰는 경우에는 세션이 곧 "현재 열려 있는 로컬 git 저장소"이므로, 별도 선택 절차 없이 해당 디렉토리에서 `claude`를 실행하면 그 저장소가 자동으로 컨텍스트가 됩니다.

## 2. 선택한 저장소는 어떻게 쓰이나요?

- 세션은 지정된 저장소를 **fresh clone**한 뒤, 작업 전용 브랜치(예: `claude/기능명-랜덤해시`)를 만들어 그 위에서 작업합니다. 원본 브랜치(main/master)에 직접 커밋하지 않습니다.
- 커밋은 이 작업 브랜치에 쌓이고, 필요 시 PR을 만들어 원본 브랜치로 병합을 제안합니다. PR 생성은 명시적으로 요청받았을 때만 수행합니다.
- 한 세션에서 **여러 저장소를 동시에** 다룰 수도 있습니다(`add_repo`로 추가). 예: 프런트엔드/백엔드 저장소가 분리되어 있고 한 기능이 양쪽을 모두 수정해야 하는 경우.
- 세션이 끝나거나 일정 시간 비활성 상태가 되면 격리된 컨테이너(작업 디렉토리)는 회수됩니다. **커밋 후 push하지 않은 변경사항은 사라질 수 있으므로**, 의미 있는 결과물은 항상 push까지 완료해야 안전합니다.
- 환경(environment) 설정(네트워크 정책, 환경 변수, 셋업 스크립트 등)은 저장소와 별개로 세션 생성 시 선택하며, `list_environments`로 확인할 수 있습니다.

## 3. 작업마다 새 저장소를 지정해야 하나요?

**아니요, 매 작업마다 새 저장소를 지정할 필요는 없습니다.** 기준은 "저장소"가 아니라 "작업의 성격"입니다.

| 상황 | 권장 방식 |
|---|---|
| 같은 저장소에서 이어지는 작업(버그 수정 후 추가 요청 등) | 같은 세션을 계속 사용하거나, 필요 시 같은 저장소로 새 세션 생성 |
| 같은 저장소 + 서로 무관한 여러 기능 작업을 병렬로 진행하고 싶을 때 | 저장소는 같지만 **세션(및 브랜치)은 따로** 만드는 것을 권장 — 세션마다 독립된 브랜치를 쓰므로 서로 충돌하지 않음 |
| 완전히 다른 프로젝트/저장소 작업 | 그 저장소를 스코프로 하는 **새 세션**을 생성 (또는 진행 중인 세션에 `add_repo`로 추가) |
| 여러 저장소에 걸친 연관 작업(모노레포처럼 다뤄야 할 때) | 한 세션에서 `add_repo`로 필요한 저장소를 모두 추가해 함께 진행 |

정리하면:
- **저장소 자체는 재사용**해도 됩니다 — 매번 새로 "지정"할 필요는 없고, 이미 연결돼 있으면 세션 생성 시 고르기만 하면 됩니다.
- **세션(작업 브랜치)은 작업 단위로 분리**하는 것이 좋습니다. 하나의 세션 = 하나의 논리적 작업/PR이라고 생각하면 충돌이나 컨텍스트 혼선을 줄일 수 있습니다.
- 이미 병합(merge)된 PR의 세션은 재사용하지 않고, 후속 작업은 최신 기본 브랜치에서 새로 브랜치를 딴다고 생각하면 됩니다.

## 4. 빠른 체크리스트

1. 작업할 저장소가 `list_repos`에 있는가? 없으면 GitHub 연결/App 설치부터.
2. 이 작업이 기존 진행 중인 세션의 연장선인가, 아니면 새로운 독립 작업인가?
   - 연장선 → 기존 세션 계속 사용
   - 새 작업(같은 저장소라도) → 새 세션(=새 브랜치) 생성 고려
3. 여러 저장소를 함께 건드려야 하는가? → `add_repo`로 필요한 저장소를 세션에 추가
4. 결과물은 항상 커밋 후 push까지 완료 (컨테이너는 비활성 시 회수됨)
