# Claude Code 저장소 선택 및 사용 가이드 (초보자용)

GitHub와 Claude Code를 처음 쓰는 분을 위한 가이드입니다. 낯선 용어는 처음 나올 때 쉬운 말로 풀어서 설명합니다.

## 0. 먼저, 자주 나오는 용어부터 쉽게 정리

작업 흐름 순서대로 정리했습니다. 위에서 아래로 한 번 읽고 넘어가면 아래 내용이 훨씬 쉽게 읽힙니다.

| 용어 | 쉬운 설명 |
|---|---|
| **저장소 (Repository, 줄여서 "레포")** | 하나의 프로젝트를 담아두는 폴더라고 생각하면 됩니다. 코드 파일들과, 그 파일들이 언제 어떻게 바뀌었는지에 대한 기록(이력)이 통째로 들어있습니다. GitHub는 이 폴더를 인터넷에 올려두고 여러 사람이 같이 볼 수 있게 해주는 서비스입니다. |
| **GitHub** | 저장소를 인터넷에 올려두고 관리하는 웹사이트/서비스. "구글 드라이브"의 코드 버전이라고 생각하면 이해가 쉽습니다. |
| **클론 (Clone)** | GitHub에 있는 저장소를 내 컴퓨터(또는 작업 환경)로 통째로 복사해오는 것. |
| **브랜치 (Branch)** | 저장소 안에서 "원본은 건드리지 않고 시험 삼아 수정해볼 수 있는 복사본 작업 공간". 나뭇가지처럼 원본에서 갈라져 나와 독립적으로 수정할 수 있고, 문제없으면 나중에 원본에 다시 합칠 수 있습니다. 보통 원본 브랜치는 `main`이라고 부릅니다. |
| **커밋 (Commit)** | 파일 변경 내용을 "저장"하는 단위. 게임의 세이브 포인트와 비슷합니다 — "이 시점까지 이런 변경을 했다"는 스냅샷을 기록에 남깁니다. |
| **푸시 (Push)** | 내 작업 환경에 쌓인 커밋(저장 기록)을 GitHub(인터넷)에 업로드하는 것. 푸시하지 않으면 내 작업 환경에만 있고, 작업 환경이 사라지면 그 변경 내용도 함께 사라질 수 있습니다. |
| **풀 리퀘스트 (Pull Request, PR)** | "제 브랜치에서 이렇게 수정했는데, 원본(main) 브랜치에 합쳐주세요"라고 요청하는 것. 다른 사람이 검토(리뷰)한 뒤 승인하면 병합됩니다. |
| **머지 (Merge)** | 브랜치에서 작업한 내용을 원본 브랜치로 실제로 합치는 것. PR이 승인되면 보통 머지로 마무리됩니다. |
| **세션 (Session)** | Claude Code가 여러분을 대신해 코드를 작업하는 하나의 "작업 창(대화)". 세션 하나를 시작할 때 "어떤 저장소에서 작업할지"를 지정하게 됩니다. |
| **이슈 (Issue)** | 저장소 안에서 "할 일/버그/요청 사항"을 적어두는 게시글 같은 것. |

> 비유로 정리하면: **저장소**는 프로젝트 폴더, **브랜치**는 그 폴더의 "작업용 사본", **커밋**은 사본 안에서의 저장(세이브), **푸시**는 그 저장을 인터넷(GitHub)에 업로드, **PR**은 "이 사본 내용을 원본에 합쳐주세요"라는 요청, **머지**는 실제로 합치는 행위입니다.

## 1. 저장소는 언제, 어떻게 선택하나요?

- 저장소는 **Claude Code 세션(작업 창)을 새로 만드는 시점**에 고릅니다. 세션을 만들 때 "이 프로젝트(저장소)로 작업해줘"라고 지정하는 것이라고 보면 됩니다.
- 한 번 세션이 시작되면, 그 세션이 접근할 수 있는 저장소 목록은 **그 시점에 고정**됩니다. 작업 도중에 "아 다른 저장소도 필요하네" 싶으면 자동으로 열리지 않고, 명시적으로 추가해야 합니다(`add_repo` 기능 사용).
- 원하는 저장소가 목록에 안 보인다면 둘 중 하나가 안 된 것입니다:
  1. GitHub 계정이 Claude와 연결되어 있지 않음 → claude.ai/connect-github 에서 연결
  2. 그 저장소(혹은 저장소가 속한 조직)에 "Claude" GitHub 앱이 설치되어 있지 않음 → github.com/apps/claude/installations/select_target 에서 설치
- 컴퓨터 터미널에서 `claude` 명령어로 직접 쓰는 경우에는 별도로 "선택"하는 절차가 없습니다. 터미널에서 지금 열려 있는 폴더(저장소) 자체가 곧 작업 대상이 됩니다.

## 2. 선택한 저장소는 실제로 어떻게 쓰이나요?

1. 세션이 시작되면 지정한 저장소를 새로 **클론**합니다(항상 깨끗한 최신 상태로 가져옴).
2. 원본 브랜치(`main`)를 직접 건드리지 않고, 작업 전용 **브랜치**를 새로 만듭니다. (예: `claude/기능이름-abcd1234` 처럼 자동으로 이름이 붙습니다.)
3. 코드를 수정하면서 의미 있는 단위마다 **커밋**(저장)을 남깁니다.
4. 작업이 끝나면 그 브랜치를 GitHub로 **푸시**합니다. 이 시점부터 여러분의 GitHub 계정에서도 그 변경 내용을 확인할 수 있습니다.
5. 필요하면(그리고 요청하신 경우에만) 그 브랜치로 **PR(풀 리퀘스트)**를 만들어, 원본 브랜치에 합쳐달라고 제안합니다.
6. 여러 저장소를 동시에 다뤄야 하는 작업(예: 프런트엔드 저장소 + 백엔드 저장소를 함께 수정)이라면, 한 세션에 저장소를 추가로 연결(`add_repo`)해서 같이 진행할 수 있습니다.

**중요**: 세션이 끝나거나 한동안 사용하지 않으면 작업 환경(컨테이너)은 정리(삭제)됩니다. **커밋만 하고 푸시를 안 했다면 그 변경 내용은 사라질 수 있습니다.** 그래서 결과물이 의미 있다면 항상 "푸시까지" 끝내는 게 안전합니다.

## 3. 작업마다 새 저장소를 지정해야 하나요?

**아니요. 저장소를 매번 새로 지정할 필요는 없습니다.** 헷갈리기 쉬운 부분이라 다시 짚으면:

- **저장소(프로젝트 폴더)**는 한 번 연결해두면 계속 재사용합니다. "국민은행 사이트"라는 프로젝트가 있으면, 그 프로젝트 저장소는 하나로 쭉 씁니다.
- 대신 **세션(작업 창)과 브랜치(작업 사본)는 "작업 하나"마다 나누는 것**을 권장합니다. 왜냐하면 세션마다 독립된 브랜치를 만들기 때문에, 여러 작업을 같은 세션에서 뒤섞으면 서로 다른 목적의 변경이 한 브랜치에 섞여 나중에 정리하기 어려워지기 때문입니다.

정리하면 다음과 같습니다.

| 상황 | 저장소는? | 세션(작업 창)은? |
|---|---|---|
| 같은 프로젝트에서 하던 작업을 계속 이어감 | 그대로 재사용 | 기존 세션 계속 사용 |
| 같은 프로젝트에서 완전히 다른 새 기능/버그를 시작함 | 그대로 재사용 | **새 세션**(= 새 브랜치)을 만드는 게 깔끔함 |
| 아예 다른 프로젝트 작업 | **새 저장소**를 세션에 연결 | 새 세션 생성 (또는 기존 세션에 `add_repo`로 추가) |
| 한 작업이 여러 프로젝트(저장소)에 걸쳐 있음 | 필요한 저장소 여러 개를 한 세션에 추가 | 같은 세션에서 함께 진행 |

한 줄 요약: **"저장소"는 프로젝트 단위로 재사용, "세션/브랜치"는 작업 단위로 새로 만드는 것**이 기본 원칙입니다.

## 4. 처음 시작할 때 체크리스트

1. GitHub 계정이 Claude와 연결되어 있는가? (연결 안 됐으면 claude.ai/connect-github)
2. 작업할 저장소에 Claude GitHub 앱이 설치되어 있는가?
3. 지금 하려는 작업이 "기존 작업의 연장"인지 "새로운 작업"인지 먼저 구분한다.
   - 연장 → 기존 세션에서 계속
   - 새 작업 → 새 세션(새 브랜치)으로 시작
4. 여러 저장소를 같이 건드려야 하면 세션 안에서 필요한 저장소를 추가한다.
5. 작업이 끝나면 커밋뿐 아니라 **푸시까지** 확인한다 (안 그러면 작업 환경 정리 시 사라질 수 있음).
